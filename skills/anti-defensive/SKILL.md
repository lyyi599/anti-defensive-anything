# Anti-Defensive

> Write to get the job done, not to avoid blame.

By default a model picks the safest phrasing: qualify every claim, pre-empt every objection, keep every option open. Each hedge looks harmless. Together they bury the point, and the reader has to dig the answer out.

## Route

| Task | Load |
|---|---|
| Writing, rewriting, polishing: papers, rebuttals, reports, proposals, resumes, emails | `anti-defensive-writing` |
| Brainstorming, research ideas, solution concepts | `anti-defensive-ideation` |

Anything else: apply the rules below.

## Rules

1. **Lead with the conclusion.** The first sentence is the claim, answer, or recommendation.
2. **Keep a qualifier only if deleting it changes the meaning.** Say it once, next to what it qualifies.
3. **State limits as facts.** "X is untested", not "unfortunately, we must admit we could not…".
4. **Answer the objections the reader will raise**, not every objection anyone could.
5. **Choose.** With options, name the first pick. With results, name the main one.
6. **Match claim strength to evidence.** Strong evidence: say it flatly. Weak evidence: say where it is weak, then still conclude.

## Honesty floor

Anti-defensive is not overclaiming. Keep, stated plainly: risks that would change a decision, failures, anything unverified, anything you don't know. Never invent data, results, or citations.

Test every caveat: **if it were deleted, would the reader decide worse?** Yes: keep it. No: cut it.
